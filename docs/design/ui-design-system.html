01设计基础

DSH Phone 的界面由两层构成：原生壳（启动页 + 系统栏 + WebView）与 dsh 页面（WebView 内 SPA）。设计系统的首要任务不是"好看"，而是让这两层在深浅色切换时不出现割裂——r79/r103/r104 三代修复全部源于此。

主题判定：两段式

启动页阶段 WebView 尚未加载，读不到 dsh 主题 → 按系统 uiMode 猜测； 页面加载完成后由 detectDark() 回传真实主题并修正、落盘供下次冷启动。

铁律：缓存只能由权威信号覆盖系统。探测失败时宁可跟随系统，也不能把一次错误的猜测固化（r79 真机因此出现过"浅色启动页 + 深色页面"）。

系统栏与首页必须同色

深色下系统栏取 #151517（真机取样自 dsh 首页），而启动页底是 #141B23。 两者刻意分开：一个对齐首页、一个属于我们自己。

两者相差 R=1 / B=5，但大面积纯色相邻时肉眼可见"发蓝"——这正是 r104 修复的问题。首页改底色时必须重新量一次。

注入层的三条铁律

我们的 UI 是注入到 React 应用里的，不是自己的页面：

① 类名带 dshmine_ 前缀，且内含 _navCell 等子串以复用 dsh 原生样式；
② append-only——绝不移动/删除 dsh 的节点；
③ 幂等标记 data-dsh-* 挂在我们自己创建的节点上。
r78 的图标消失就是违反 ③：标记挂在 dsh 节点上，React 重渲染清空子节点但保留属性 → 标记在、内容没了 → 幂等早退，永远补不回来。

产品现状一句话总览（r108）

当前产品 = 原生启动页（DshPalette 取色，两段式主题）+ dsh SPA（首页 / 对话页 / 设置一级与子页——通用设置 / 模型 / 插件（配置·列表·市场）/ 主题设置，全部由 dsh 渲染） + 注入层（汉堡与抽屉、抽屉两行（插件/导出）、设置列表的 NAS 同步与存储目录项、市场徽标、三个浮层——导出 / 存储目录 / NAS 同步、Toast、空状态）。 本章之后的所有规格，均以这个真实结构为基准，不再描述理想态。

Toast 的深色语义别名（为什么不直接复用 --dsh-*）

Toast 底色固定为 --ds-ink-900（浅色主题下也是深色 pill）。若直接引用 var(--dsh-info)，浅色主题下它是 #1466B8，在深 toast 上只有 2.99:1（FAIL）。

--dsh-toast-ok #3DDC97 · 9.79:1 --dsh-toast-warn #F5B544 · 9.54:1 --dsh-toast-err #FF7A70 · 6.81:1 --dsh-toast-info #5AA9F5 · 6.94:1
四个别名定义在 .dsh-mo-toast 上，值取自深色语义色——同一来源、不同负载，改深色语义色时 toast 自动跟随。

09交付规范

改这个项目时最容易出事的地方不是配色，而是"改了 dsh 的东西"。以下为落地时的硬性约束。

注入铁律（违反即线上崩）

  1. 不搬不删 dsh 节点：React 卸载时对不在其列表里的节点 removeChild → NotFoundError 整页崩。只能 append。
  2. 标记挂自己创建的节点：data-dsh-* 若挂在 dsh 节点上，React 重渲染后"标记在、内容没了"，幂等检查永远早退（r78 根因）。
  3. 幂等检查要同时验证内容：不能只查标记存在，必须查子节点（如图标 svg）是否还在。
  4. 类名蹭子串：dshmine_navCell 内含 _navCell，可复用 [class*="_navCell"] 规则，无需重写样式。
  5. 注入 button 要清默认样式：appearance:none;border:0;font:inherit，否则多一圈灰框，看着像被选中（r77 回归）。

CSS 坑位清单

  • width:100% + padding + border → 必须 box-sizing:border-box。
  • flex 卡片用 align-self:center 会按内容收缩导致宽度不等；改用 width:100% + max-width。
  • 深色下的渐变末端必须是底色透明，写死白透明会泛白雾。
  • Java 字符串拼接里注释必须独占一行；行内注释会让下一行 + 变一元运算符，报错却指向别处。
  • Toast 不能直接引用 --dsh-*（浅色值在深底上 FAIL），用 --dsh-toast-* 别名。

设计走查清单

  • 浅/深两套主题各截一次图，重点看系统栏与首页交界。
  • 新增列表项后检查 label 左边距是否统一为 64px。
  • 新增浮层后确认 z-index 在 80+ 区间取号（现有 80/81/82）。
  • 改任何文字色后跑一次对比度实算，别凭肉眼。
  • 改完 mobile.css/js 必须跑 scripts/sync-from-source.sh + headless 实测再提交。

8 张页面稿里，有 4 张的主体是 dsh 自己的 React 页面（首页输入主卡、插件市场、设置页原生四项、页面主题切换）。 我们的代码是注入到它里面的，受铁律约束——不搬不删 dsh 节点， 所以只能覆盖样式、补齐节点，不能重写页面结构。

因此页面稿是校验基准（用来判断注入的 UI 与周围是否协调），不是"照着重写一遍"的施工图。 把这点混为一谈，就会觉得"差得很多"却无从下手。
