## 0. 方法论：三条让人白跑整轮的陷阱

这三条都真实发生过，而且都伪装成"技术问题"，其实是环境/工具问题。

### 0.1 curl 测 localhost 会被代理劫持 → 假 404

环境里有全局 `http_proxy`，`curl http://127.0.0.1:3099/` **会被代理接管**，
返回的是代理的 404/502（body 是中文 `upstream connect failed…`）。
曾据此得出"UI 不在根路径"的错误结论，排查了一整轮。

```bash
curl --noproxy '*' http://127.0.0.1:3099/     # 正确
node -e "fetch('http://127.0.0.1:3099/').then(r=>console.log(r.status))"  # 也行
```

### 0.2 Windows 上 Node 不认 `HOME` 环境变量

Node 用 `USERPROFILE` / `os.homedir()`。设 `HOME=...` 不生效，
profile 目录会落在 `C:\Users\<你>\.dsh\...`，于是解析不到 D 盘的 `node_modules`，
复现出来的环境和手机完全不同。**要让 node 换家目录，得设 `USERPROFILE`。**

### 0.3 `File.list()` 只返回顶层条目

完整性校验里写 `new File(dist,"assets").list().length` 去跟 **递归** 条目数比，
结果永远不达标 → 每次启动都误判"文件缺失" → 白白重解包 736MB → 解包后仍然不达标 →
抛异常拒绝启动。**把自己锁死在死循环里。**

正确做法：要么递归统计（迭代实现，避免爆栈），要么只校验少量**确定存在**的关键文件。
实际值参考：`dist/assets` 顶层 6 项（`fonts/`、`langs/` + 4 个文件），递归 86 个文件。

## 1. 服务起不来 / 起一半就退

### 1.1 koffi 找不到原生模块 → 整个 cordis profile 加载失败

```
Error: Cannot find the native Koffi module; did you bundle it correctly?
  → failed to import loader entry subprocess (@deepseek-ai/dsh-subprocess-local)
  → failed to import loader entry sandbox (@deepseek-ai/dsh-sandbox-local)
Error: dsh: plugin tree failed to load
```

koffi 的加载器只在**两处**找本机二进制：

1. `node_modules/@koromix/koffi-<platform>-<arch>`
2. `node_modules/koffi/build/koffi/<platform>_<abi>/koffi.node`（`<abi>` = `process.arch`）

bundle 里只有 `@koromix/koffi-android-arm64/android_arm64/koffi.node`，**没有 `build/` 目录**。
Termux 的 node 可能报 `platform=linux` 也可能报 `android`，两个路径都铺最稳
（`DshBootstrap.ensureKoffiNative()` 就是这么做的，每次启动幂等检查）。

### 1.2 缺 `--expose-internals` → boot 完立刻崩

```
Error: --expose-internals is required for HMR service
  at new Hmr (cordis-plugin-hmr/lib/index.js:107)
```

web profile 是 `patchReload: "live"`，`runProfile` 会在 boot 之后创建 `cordis-plugin-hmr`，
缺这个 flag 就抛错退出。启动命令必须带：

```bash
node --expose-internals .../dsh/lib/bin.js web --port 3080 --no-open
```

### 1.3 `setsid` / `nohup` 不存在 → 服务静默不启动

bundle 里没有 coreutils。**不要用 `cmd &` + `waitFor`**——`Runtime.exec` 的子进程会随调用栈结束被回收。
直接用 `ProcessBuilder` 起 bash 脚本本体并持有 `Process` 引用，`stop()` 时 `destroy()`。

### 1.4 日志重定向到不存在的目录 → 什么都看不到

`$HOME` 必须先 `mkdirs()`，否则重定向失败、连日志文件都不会生成。
现在 `tailLog()` 在日志缺失时会输出一份环境自检清单（HOME/bash/node/脚本/libc++/libicuuc）。

## 2. 服务起来了但页面打不开

### 2.1 裸根路径返回 401，必须走带 token 的 URL

```
HTTP/1.1 401  dsh web authentication required; reopen the URL printed by dsh web.
```

dsh 的握手是：

```
启动时 stdout 打印  dsh web: http://127.0.0.1:3080/?token=xxxx
   ↓ 打开这个 URL
303 + Set-Cookie: dsh-auth-<sha256(authority)>=v1.<payload>.<sig>;  HttpOnly; SameSite=Strict
   ↓ 浏览器带 cookie 重定向回 /
200 text/html（27,660 字节的 index.html）
```

**token 每次启动都变**，必须每次从日志重新抓。App 的做法：
`DshProcessManager.readTokenUrl()` 正则抓最后一条，然后 `DshProbe` 用 Java 侧完成握手、
把 cookie 显式写进 `CookieManager`，**不再依赖 WebView 的 303/cookie 行为**。

### 2.2 `net::ERR_HTTP_RESPONSE_CODE_FAILURE` 只说明一件事

Chromium **只在「4xx/5xx + 空响应体」**时给这个错误。把 dsh 的 webserver 和
frontend-static 源码通读一遍，能产生空响应体的只有 4 条：

| 状态码 | 触发条件 |
|---|---|
| **400** | 路由 handler 抛异常（webserver 的 catch：`writeHead(400); end()`） |
| **403** | 路径穿越检查 |
| **404** | `readFile(dist/index.html)` 抛 ENOENT/EISDIR/ENOTDIR |
| 405 | 非 GET/HEAD |

注意 **401 是带响应体的 `text/plain`**，而 `authorizeIndex` 里 `tokenMatches` 有长度守卫
（`byteLength` 相等才比），所以"token 被截断"只会得到 401，不会得到 400。

### 2.3 401 vs 400 怎么区分

`DshProbe` 在手机上跑一遍完整握手并把**原始证据**打在屏幕上：
① 带 token 请求的状态码 / Location / Set-Cookie ② 裸 `/` ③ 带 cookie 的 `/`
④ dist 落盘检查 ⑤ 可用空间 + 上次是否触发过修复 ⑥ 服务日志末 25 行。

**400 一定能从日志里看到 `ctx.logger.warn(err)` 的真实堆栈**（webserver 写 400 之前会先 log）。

## 3. 打包 / 解包

### 3.1 bundle 扁平布局 + 软链丢失

早期用 `tar -C $PREFIX bin/node lib/... node_modules` 打成扁平结构，
而 App 按 `usr/bin`、`usr/lib`、`home/node_modules` 去找 → 真机上 bash/node/.so 全部"缺失"。
用 `04-repack-bundle-layout.py` 重排。

### 3.2 必须保留符号链接

node/bash 的 NEEDED 是**短名**（`libz.so.1`、`libicuuc.so.78`、`libsqlite3.so`），
真实文件带完整版本号，短名在 Termux 里正是软链。`tar` **不要加 `-h/--dereference`**，
一旦 dereference 或"先解包再重打包"，软链就全丢 → 运行时 `library not found`。

短名缺失时用 `llvm-readelf -d` 扫 ELF 的 NEEDED/SONAME 补软链，
但**别名只限 lib 顶层且必须确认目标存在**——否则会给 krb5 子目录插件造出悬空软链。

### 3.3 tar 长路径 → `FileNotFoundException ... open failed: EISDIR`

ustar 的 `name` 只有 100 字节，`prefix` 155 字节；`prefix` 为空时超长路径被截成两段，
解包时就会 `EISDIR`。解包器必须做 **`name(100) + prefix(155)` 拼接**，
并且支持 GNU `'L'`（长名）/ `'K'`（长链接名）/ `'2'`（符号链接）/ base-256 大小。
打包侧用 `tarfile.GNU_FORMAT`。

### 3.4 AGP 会把 assets 里的 `.gz` 解压并去掉后缀

APK 里实际是 `assets/dsh-bundle.tar`（纯 tar，首字节 `0x6e 0x6f` = "no"）。
判断要不要 gunzip **必须用魔数 `0x1f 0x8b`**，不能看扩展名。

### 3.5 解包写失败会留下"永久残档"

解包器遇到 `FileNotFoundException` 只打一条日志就继续，**然后照样写 stamp** →
之后每次升级都因 stamp 命中而跳过解包 → 缺的文件永远补不上。
典型触发是**存储空间不足**（tar 内容 736MB，峰值需 ~740MB）。

现在的做法：
- 解包器统计 `skippedCount`，>0 就**不写 stamp**、直接中止，下次启动重试；
- 解包**之前**检查可用空间（阈值 900MB），不足就明确报错；
- 每次启动抽查 12 个关键文件 + `dist/assets` **递归**文件数，缺任何一项自动清理重解包。

## 4. Termux 二进制的硬编码路径

Termux 编译的二进制里 `/data/data/com.termux/files/usr` 与 `.../home` 是**编译期写死**的。
我们的包名是 `com.dsh.harness`，所以那些路径全部指向别的应用 → OpenSSL 报
`fopen(/data/data/com.termux/files/usr/etc/tls/openssl.cnf, rb) Permission denied`。

当前用低风险手段覆盖（按优先级）：

1. **环境变量**：`SHELL` / `TMPDIR` / `SQLITE_TMPDIR` / `OPENSSL_CONF` / `OPENSSL_MODULES` /
   `LD_LIBRARY_PATH` / `NODE_OPTIONS`（含 `--require shim`）
2. **现场生成 `usr/etc/tls/openssl.cnf`**：最小 OpenSSL 3 配置（`openssl_conf → providers →
   default activate=1`）
3. **node 预加载 shim**（`usr/libexec/dsh-node-shim.js`，`--require` 注入）：
   把 `child_process` 的 `exec/execSync/execFile/execFileSync/spawn/spawnSync`
   的默认 shell 从 Termux 硬编码路径改成 `$PREFIX/bin/bash`。
   ⚠️ 必须**逐个包裹**——node 内部的 exec 调用是局部 spawn，环境变量盖不住。

升级手段（未做）：自写 `LD_PRELOAD` shim，在 `open/openat/execve/posix_spawn` 里重写路径
（Termux 自己也用 `LD_PRELOAD` 做类似的事）。

## 5. WebView / 前端

### 5.1 桌面布局在手机上挤成竖排

`dsh-client-ui-layout/lib/client.js`：

```js
const narrow = viewport < SIDEBAR_AUTO_COLLAPSE;            // = 1024
const sidebarCollapsed = narrow ? !layoutInfo.narrowExpanded : layoutInfo.sidebar === 0;
const sidebarPreference = sidebarCollapsed ? 0 : (layoutInfo.sidebar === 0 ? 280 : layoutInfo.sidebar);
```

`narrowExpanded` 初值 **true** → 窄屏下 `sidebarCollapsed` 恒为 false → **侧栏永不自动折叠**，
宽度还直接取默认 **280px**。393px 的手机屏幕上，中间对话区被压成一条竖排。
另外侧栏**没有覆盖层形态**，展开时永远是并排的网格列。

修法见 `MobileTuning.java`：注入窄屏 CSS（限宽侧栏 + `!important` 盖过 React 的行内
`grid-template-columns`）+ 点一次折叠按钮（走应用自己的状态机，状态会自己持久化）。

### 5.2 附件点了没反应

**Android WebView 默认不实现 `WebChromeClient.onShowFileChooser`**：
`<input type="file">` 被点击时既不弹选择器、也不回调。必须由宿主 App 接上
`ACTION_GET_CONTENT`，并在 `onActivityResult` 里**先于 `super`** 把结果回灌。

### 5.3 定位 dsh 前端元素的窍门

dsh 的界面文案**不在** `dist/assets/index-*.js` 里，而在运行时加载的插件 client bundle
（`/plugins/??...` → 对应包的 `lib/client.js`）。要拿到稳定的 DOM 选择器，
直接去 `@deepseek-ai/dsh-client-ui-sidebar/lib/client.js` 之类的包里看 JSX。

好用的钩子：
- `button[aria-label="收起侧边栏" | "Collapse sidebar"]`（i18n key：`toggle.collapse` / `toggle.open`）
- AppFrame 的 div 带 `data-sidebar-collapsed` / `data-rightbar-collapsed` /
  `data-rightbar-fullscreen` 等 **data 属性** —— 比哈希类名更适合判状态
- 类名 `frame` / `handle` 在该 CSS module 内唯一（已 grep 确认），`[class*=...]` 选择器安全

## 6. Windows 构建环境

| 坑 | 说明 |
|---|---|
| **工程路径含空格** | `ndk-build.cmd` 批处理 → "APP_BUILD_SCRIPT points to an unknown file"。**junction 无效**（Gradle 解析回原路径），必须 `mv` 到无空格路径 |
| 全量 `clean` | 会触发 bootstrap 资源重下，卡 30+ 分钟。增量就删 `outputs/apk` + `intermediates/{assets,compressed_assets}` |
| Gradle 代理 | Java TLS 握手会被代理中断，必须写 `gradle.properties` 的 `systemProp.http(s).proxy*`；**端口会变**，`env \| grep -i proxy` 现查 |
| GitHub 大文件 | 走 `https://gh-proxy.com/<原始URL>`，比 codeload 快两个数量级 |
| `javac` 源码校验 | 必须 `-encoding UTF-8`（默认 GBK 报"不可映射字符"）；javac 在 `D:\AndroidSDK\jdk17\bin\javac.exe` |
| Gradle 任务名 | 只有 `:app:assembleDebug`，**没有** `assembleArm64-v8aDebug` |
| `targetSdkVersion` | 故意保持 **28**（Termux 靠它避开 SELinux 对子进程的限制），但也因此必须在 Manifest 显式放开明文流量 |
| git 全局代理 | 环境里写死的 `http.proxy` 常是失效端口，`git submodule` 只认全局配置 → 会静默卡死，必须 `-c http.proxy=...` 显式传 |

## 7. 排查手法备忘

- **改多个文件时不要并发 Edit**：同一文件并发会互相覆盖，且工具仍报 success。改完必须 `grep` 复核。
- **测本地服务别用默认 curl**（见 0.1）；**测 node 程序别改 HOME**（见 0.2）。
- 交付 APK 前固定自检：zip CRC、条目数、尾部空隙（防 Gradle 增量打包产生孤儿数据）、
  dex 里搜关键字符串、`aapt2 dump badging` 确认包名/版本/入口。
- 常量在 dex 里搜不到字面量时，记得 javac 会**内联**（如 `ACTION_GET_CONTENT`
  → `android.intent.action.GET_CONTENT`）。
